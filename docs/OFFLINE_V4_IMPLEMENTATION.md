# Offline V4 — 审查问题修复

## 范围

修复 V3 的几何失效闪烁、估计状态误标和主前端版本混用。仍是实验标定，不是已验证精度的完整 CAROM 复现。原 V3 结果和首轮 V4 试验输出保留作对照。

## 几何可用性与检测生命周期分开

- 检测连续三帧确认 ID；丢失超过 18 帧退役且 ID 不复用，这一规则不变。
- 已初始化的世界状态遇到体积框拟合失败，进入有界运动预测，而非以“几何拟合失败 18 帧”直接清空平面位置。
- 延长到短时检测保留窗口之外时，需要至少 3 次接受的位置量测。预测最长 2 秒，条件位置协方差最大轴标准差至多 2.5 名义米，位置须仍在有效区域内。
- 门槛只是运行参数，不是定位精度保证；协方差未包含标定误差。超限显式报告 `geometry_prediction_timeout`、`prediction_uncertainty_exceeded` 等原因。没有历史位置的对象仍待定位，不伪造初始坐标。
- 首轮仅放宽时间的实验让重叠从 18 增至 28 个车辆对—帧，因此加入量测成熟度门槛，避免单次拟合后长期外推。未根据碰撞结果删除或移动车辆。

## 量测与结果语义

RTS 处理的结果一律为 `geometry_status=smoothed`，并使用 `measurement_status=accepted/rejected/missing` 表示当前量测是否被采用。原始几何状态、原因、位置、速度、朝向存于 `online_estimate`。图中 S 为离线平滑、P 为在线预测。

未经 RTS 的短片段仍保留 measured/predicted/pending，避免误报处理范围。计数按最终状态重新汇总，原始在线计数独立保存。

## 前后端

主前端全部切换到 `/api/carom-method`，默认后端输出为 `carom-offline-v4-final`。

- `/run-info` 检查必需产物存在才发布版本信息；文件缺失返回 503，不静默展示旧 V1。
- 页面显示实际版本、数据集 ID、标定警告、每帧检测/预测/定位数及每车量测状态。
- 主视频驱动俯视视频和帧号；帧选择器暂停并定位两个视频。切换帧时不展示旧帧数据。
- 验证截图明确标为固定帧，不伪装成随视频变化的画面。
- `?legacy` 仅作为显著标注的历史页面。

## 回归与限制

单元测试覆盖：第 20 帧几何失效仍有可靠预测、检测 ID 到期、时间到期、协方差超限、有效区外、单次拟合不足以延长预测，以及未完成产物不发布。

`scripts/check_v4_regressions.py` 仅用于已知用户素材：检查 ID 8 第 57–60 帧位置连续存在、离线拒绝量测的状态正确、逐帧 ID 集合一致和输入哈希。最终统计见同目录 `verification.json`、`regressions.json` 和 `smoothing-report.json`，这些不代替真实位置/车道精度验收。

待解决：同场景实测内参及道路测绘/独立校验、遮挡后的真实身份准确率、残余重叠与体积误差、长期/多场景验证。为保持对象连续显示而增加预测覆盖，可能降低部分遮挡帧的投影轮廓贴合度；需查看原始量测与预测状态，不以平滑程度判定准确。

## 本次执行结果

89 项后端测试通过；前端 TypeScript/Vite 构建和 ESLint 通过。浏览器实测版本切换、第 58 帧 ID 8、第 37 帧 ID 15、双视频定位与播放、历史页警告；控制台无错误/警告。

240 帧回归中待定位对象—帧由 V3 的 768 降到 635；占地框重叠由 18 变为 19 个车辆对—帧，尚未消除。V4 覆盖更多预测位置，两个版本的发布集合也有变化，原始统计不等于相同样本准确率改善。
