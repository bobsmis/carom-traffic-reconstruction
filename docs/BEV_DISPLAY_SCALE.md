# 每米显示长度放大

## 本次调整

旧 BEV 使用统一的 **10 px/m**。本次增加原分辨率俯视详情：**20 px/m（两轴一致）**，每米显示长度加倍，1m网格、5m主网格与10m比例尺一并绘制。整个 100m 道路区间仍保留，不裁掉某些车辆凑出更大的间距。

这里修改的是显示映射，不是相机标定或车辆坐标。扩大图像不会纠正实际车间距估计的偏差；假设标定的误差仍存在。

## 防止再次显示压缩

- 横纵同一 px/m，车长车宽按统一矩阵投影；禁止单独拉长纵向或拉扁车体。
- 详情图/视频为 **2160×924**，地面绘图区 **2160×800**，额外124像素用于标题和比例尺。
- 此处 20 px/m 是文件原生像素比例。聊天图片、手机或播放器“适应屏幕”仍会缩小；查看原图或使用专用缩放页面可按原比例滚动查看。
- API 页面 `/api/carom-method/bev-view` 默认原比例，不使用 `width:100%` 自动挤进屏幕。提供缩放滑块、原比例和适应屏幕按钮，并显示实际 CSS 像素/米。
- 测量/预测转换时详情图保持填充透明度一致，用 `P` 标记预测，避免亮度切换被误认为大小闪烁。

## 运行

在 `/home/hcr/workspaces/carom-rebuild`：

```bash
.venv/bin/python scripts/export_bev_detail.py outputs/carom-method-wide-stable --pixels-per-meter 20
```

只重绘已计算的逐帧结果，不再次检测，不修改 `frames.jsonl`。导出前后验证该文件 SHA256 不变。新增文件：

- `bev-detail.png`：带米制网格的独立俯视图。
- `bev-detail.mp4`：原分辨率 H.264，保留原240帧/30fps，不套用1280×720的非等比例缩放。
- `validation-detail.png`：原画面/检测与大比例 BEV 合图。
- `bev-detail.json`：比例、变换矩阵、帧数据散列与渲染代码散列。

API：`/api/carom-method/bev-detail`、`bev-detail-video`、`bev-display`、`bev-view`。
