# CAROM 方法替换：实现与验收边界

## 决策

停止以旧版车道吸附、方向限制、碰撞后挪位作为几何定位修复手段。旧 V1 留作对照；新增独立的论文方法分支。尚未通过真实精度验收时，不将实验结果标为正式复现完成。

依据：
- [CAROM 官方仓库](https://github.com/duolu/CAROM)
- [2021 年固定道路相机论文](https://arxiv.org/abs/2104.00893)，方法部分 III.A–E；不是 CAROM Air。
- README 指向的 [tracking_3d 实现](https://github.com/Institute-of-Automated-Mobility/tracking_3d) 在本次检查中返回 404。本地参考仓库有论文，没有这套完整实现。因此本分支是论文指导的独立重实现，不声称复用了作者完整源码或权重。

## 方法对齐

| 环节 | 本分支 | 与原方法的差异 / 边界 |
|---|---|---|
| 场景标定 | 固定 K，地面对应点求刚体相机位姿；地面和高处角点共用 P=K[R\|t] | 严格模式要求实测 K、至少 6 对实测控制点和独立检查点；当前素材仅 4 对假设点，走显式实验模式 |
| 实例分割 | 本地 YOLO 分割；默认从原始视频推理，也支持明确标识的本地观测缓存回放 | 作者使用自有数据微调的 Mask R-CNN；当前权重不是论文权重 |
| 关联 | 上帧实例内特征 → LK 双向一致性 → 运动补偿轮廓重叠、特征落点投票 → 一对一匹配 | 匹配求解使用 Hungarian；车辆子类作为软信息，时间累计稳定类别，不因单帧分类改变另建身份 |
| 航向 | 校准地平线约束的光流消失点共识估计；累积图像运动作显式标识的初始化回退 | 确定性枚举最小假设代替随机抽样；未使用作者专用航向网络；静止新车允许待确认 |
| 体积框 | 航向确定三个轴消失点；凸轮廓切线反投影成支撑平面；求底面中心和 L/W/H | 使用带类别尺寸先验的有界最小二乘，替代未公开的经验修正规则；先验参与的尺寸不是独立实测体积 |
| 遮挡处理 | 图像截断、前景重叠、轮廓拟合质量和滤波创新门控 | 重叠深度排序仍为启发式，完整遮挡/接触地面不可见时保留不确定性 |
| 速度 | 光流特征射线与上帧拟合车体相交得到深度，以局部投影雅可比估计地面速度 | 未原样实现论文 5 m / 30 步窗口；此处是独立的局部刚体平移估计，需单独实测验收 |
| 状态估计 | 地面四维位置/速度 Kalman，位置和光流速度均作为观测；创新门控 | 道路平面假设下省去恒为零的 z/vz；禁止用车道方向强制改写运动 |
| 丢失 | 全局 ID 不回收复用；至多 18 帧匀速预测，随后停止该空间输出/回收失联轨迹 | 对检测失联和几何观测失效分别计时，预测与测量分开显示 |
| 车道 | 对几何位置作语义归属；越界明确标记 | 当前八车道仅名义宽度模型；不对车辆位置吸附或回正，不声称已实测车道拓扑 |
| BEV | 原视频多帧中值背景经同一个相机模型逆透视；全图等比例米制坐标，真实航向的尺寸框 | 不再套用异地道路图片；非地面树木等会被拉长，中值背景也可能残留慢车；它不是卫星正射图 |
| 展示 | 原画面 / 分割+ID+体积框 / BEV，提供待定位 ID 清单 | 暂用度量底面框，不以汽车贴图掩盖几何问题；最终 3D 场景继续搁置 |

## 从根源修复的旧问题

1. 地面单应性与高处车体使用不同投影：新实现只维护一个物理相机矩阵。
2. 用掩膜最低点当车体中心：替换为拟合体积框底面中心。
3. 通过平移二维矩形伪造立体框：新分支不读取或生成旧 `cuboid_image_fitted`。
4. 光流仅用于画箭头：进入实例关联、航向和速度观测。
5. 偶发类别跳变导致旧车预测与新 ID 并存：同类交通工具允许软分类匹配，并累计类别证据。
6. 为了看起来正常强制吸附、限定行进方向、删除近邻预测：新分支全部停用；交叠仅统计，不靠改坐标消除。
7. 无证据也把每个检测塞进 BEV：保留同一 ID，但定位证据不足时输出 `ground_xy: null` 与原因，不编造坐标。

最新输出是 `outputs/carom-method-wide-stable`，包含[扩大后的有效测量区](MEASUREMENT_REGION.md)与[按 ID 固定尺寸](VEHICLE_SIZE_STABILITY.md)。无 ROI 的 `outputs/carom-method-v2`、50m ROI 的 `outputs/carom-method-roi` 与 V1 均保留。独立 API 默认指向最新结果：
- `/api/carom-method/audit`
- `/api/carom-method/frames/{index}`
- `/api/carom-method/validation`
- `/api/carom-method/video`（需生成 H.264 `mobile.mp4`）

默认入口使用本地分割模型；缓存模式用于隔离检测变化、比较几何和关联方法。缓存来源和 SHA256、视频 SHA256、代码 SHA256 都记录在审计中。处理阶段没有 LLM、图像生成或外部视觉 API 调用。

## 严格校准输入约定

`planar_calibration` 中，`intrinsic_matrix` 是裁剪后、已去畸变图像坐标系下的 3×3 K；`image_points_px` 与 `ground_points_m` 一一对应，地面 z=0，单位米。`surveyed: true` 仅供真实测量数据使用，非开关式精度认证。`check_points` 另含独立的 `image_points_px` 和 `ground_points_m`，严禁复制拟合点充数。`max_check_rmse_px` 默认 3 px。非零畸变时先对视频及控制点一致去畸变，再运行。

当前四点场景刚体投影拟合的控制点 RMSE 约 **13.83 px**，没有独立检查点。这暴露了旧场景假设与物理相机之间的不一致；不是新方法测得的真实位置误差。也不应用重新挑选控制点来掩盖它。

## 验收层级与后续次序

1. **数学回归**：已知相机/已知体积的合成测试，含无限远消失点、异常光流、匀速丢失预测、分类抖动、ID 一对一、不复用 ID、统一投影。
2. **真实流程回归**：真实视频的本地缓存重处理，并另运行不使用缓存的分割烟雾测试。核查逐帧 ID、定位/预测/待确认数量、投影一致性及交叠。此层通过不代表准确率通过。
3. **场景精度验收（尚待完成）**：取得同场景可靠内参与测量点/地图，保留独立检查点；用人工核对或公开真值检验位置、尺寸、车道、IDF1/ID switch。先解决校准，不追加展示补丁。
4. **检测适配**：在上述基准固定后对比 Mask R-CNN 与当前分割器；有标注数据再决定是否微调。作者私有训练权重不是现成可复现条件。
5. **正式接入**：达到几何/身份精度标准后切换正式前端默认结果，恢复按度量尺寸渲染汽车图标。当前 V1 页面仅保留对照，不冒充新分支。

重叠数为未作后处理隐藏的原始诊断。旧 V1 使用过预测抑制等展示规则，两个版本的表面重叠计数不宜直接解释为精度提升或下降。
