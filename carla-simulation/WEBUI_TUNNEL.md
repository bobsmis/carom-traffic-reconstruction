# 隧道仿真 WebUI（本地版）

入口：http://127.0.0.1:8766/ 。重启入口：本目录 `start_webui.ps1`。

## 操作

1. 启动本地控制服务后，在网页点击“启动 CARLA”（已有服务则保持它）。
2. 设置时长、种子、变道与碰撞测试，点击“搭建并采集”。这会替换当前地图，仅清理本项目标记的资产；其他车辆/传感器存在时采集脚本停止。
3. Online 显示 RGB 抽帧预览（2 秒刷新，并非低延迟视频直播）。停止采集会保留已采集帧。
4. 采集完成后点击“运行感知与重建”；后台通过 WSL 调用既有算法。Offline/回放提供 RGB、标注、BEV 三路 H.264 视频。当前播放器独立控制，尚非严格联动时间轴。
5. 事故故障页显示最近任务的仿真事件；collision_sensor 为物理接触，lane_change_requested / collision_test_requested 只是请求。Unity 通道仍留空。

## 模块

- `control_server.py`：Windows 控制面，loopback:8766，仅白名单操作；无网页任意命令执行接口。
- `capture_tunnel.py`：CARLA 0.9.16 同步采集，双向八车道、随机入口车流、变道与物理碰撞测试。
- `carom_sim/tunnel.py`：使用 CARLA 已有 Engine Cube 网格程序化生成墙体及顶棚，非后期图像覆盖。约 248 m 长，路面净宽 28 m，顶棚下缘 20 m；工程白模，未完成灯具、正式材质和消防设施美术。
- WSL `frontend/src/Simulation.tsx`：复用现有 React 工程的新入口；原工作台保留在 5173。
- 原 CAROM 算法：仅读取 input/ 和冻结模型；控制面有权操作 CARLA，感知模块不读取 truth/。

## 边界

碰撞测试在仿真中控制独立车辆产生追尾，不伪造接触事件。入口生成采用随机间隔并检查占位；道路容量上限 32（碰撞对可额外增加两辆）。变道请求使用 TM，事件与实际车道迁移分别核查。

本服务仅绑定本机，不对公网开放。公开部署前还需身份认证、任务持久化、权限隔离和配额。当前是文件/进程约定隔离，尚非 OS 级真值隔离。更换场景不代表已有算法已达到高精度，原生隧道会引入新的光照和遮挡挑战。

退出控制服务不会自动终止 CARLA。重新启动控制服务前先停止采集，避免两个同步 tick 客户端；当前控制服务单任务互斥。
